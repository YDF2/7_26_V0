# 2026-04-18 键盘遥控模式接入与FSM安全策略工作日志

## 背景与目标

在 Orin 载板 SSH 终端场景下，为机器人新增键盘遥控模式，满足以下要求：

1. 启动参数可切换自动模式与键盘遥控模式。
2. 键盘 `wasdqe` 控制移动和旋转。
3. 按 `k` 触发踢球动作。
4. 头部在手动模式下持续执行“找球 -> 跟踪球”。
5. 始终优先检测跌倒并执行对应起身动作。
6. 速度参数放入 `data/config.conf`，便于随时调参。

## 本轮改动清单

### 1) 启动参数新增 `controlflag`

修改文件：

- `src/controller/options/options.hpp`
- `src/controller/options/options.cpp`

改动说明：

1. 新增 `-f/--controlflag` 参数，默认 `0`。
2. 语义定义：
   - `controlflag=0`：保持现有逻辑（GC/FSM 或远程 TCP）。
   - `controlflag=1`：进入 SSH 键盘遥控模式。
3. 新增 `Options::control_flag()` 访问接口。

### 2) Player 接入键盘线程与手动控制路径

修改文件：

- `src/controller/player/player.hpp`
- `src/controller/player/player.cpp`

改动说明：

1. 新增手动控制相关成员：
   - 输入线程、运行标志、终端 raw 模式状态。
   - 原子控制量 `manual_x_/manual_y_/manual_d_/manual_enable_`。
   - 按键时间戳、踢球请求和冷却时间戳。
2. 新增函数：
   - `start_manual_control()`
   - `stop_manual_control()`
   - `manual_control_loop()`
   - `apply_manual_key(char key)`
   - `play_manual()`
3. 主循环优先级调整：
   - `controlflag=1` 时优先走 `play_manual()`。
   - 否则保持原有 `use_remote()` 和 `think()` 流程。
4. 生命周期接入：
   - `init()` 中启动键盘线程。
   - `stop()` 中停止线程并恢复终端。

### 3) 手动模式行为设计

键位映射：

- `w`: 前进
- `s`: 后退
- `a`: 左移
- `d`: 右移
- `q`: 左转
- `e`: 右转
- `space`: 急停
- `k`: 触发 `left_little_kick`

关键逻辑：

1. **跌倒优先**
   - `play_manual()` 首先检查 `WM->fall_data()`。
   - 检测到跌倒后强制切换并执行 `FSM_STATE_GETUP`，屏蔽手动步态输入。
2. **头部策略持续运行**
   - 可见球：`LookTask(HEAD_STATE_TRACK_BALL)`。
   - 不可见球：`LookTask(HEAD_STATE_SEARCH_BALL)`。
3. **踢球安全触发**
   - `k` 触发一次性请求。
   - 主线程消费请求时先停步，再执行 `ActionTask("left_little_kick")`。
   - 增加冷却防止连发。
4. **松手自动停步**
   - 使用 `termios + select` 非阻塞输入。
   - 超过输入超时时间后自动清零步态，模拟“按键释放”。

### 4) 参数配置化

修改文件：

- `src/data/config.conf`

新增配置块：

```json
"manual_control": {
  "x": 0.04,
  "y": 0.02,
  "d": 8.0,
  "input_timeout_ms": 320,
  "kick_cooldown_ms": 1200,
  "debug_log": true
}
```

说明：

1. 前进速度使用 `x`，后退速度自动取 `-x`。
2. 左右平移速度使用 `y`。
3. 转向速度使用 `d`。
4. 可直接改配置并重启程序生效。

## 运行方式

示例：

```bash
./controller -p2 -f1
```

说明：

1. `-f1` 启用键盘遥控模式。
2. 建议通过 SSH 交互终端前台运行，确保 stdin 为 TTY。

## 验证建议

1. 启动后按 `wasdqe`，确认步态响应方向正确。
2. 松开按键，确认机器人在超时后自动停步。
3. 按 `k`，确认执行 `left_little_kick` 且有冷却限制。
4. 手动制造前倒/后倒，确认优先进入起身流程。
5. 起身完成后，确认可恢复键盘控制。
6. 观察头部行为，确认有球跟踪、无球搜球。

## 风险与注意事项

1. SSH 会话断开时，输入线程不再收到按键；程序退出时会尝试恢复终端模式。
2. 键盘模式是“完全绕过裁判盒状态控制”的设计，适合调试与人工操控，不建议用于正式比赛流程。
3. `left_little_kick` 动作依赖现有动作文件，请确保动作定义存在且稳定。

## 结论

本轮已完成键盘遥控模式接入，满足“移动+旋转+踢球+头部跟踪+跌倒起身优先”的组合要求，并将关键速度/时序参数外置到 `config.conf`，可现场快速调参。

## Bug修复增量（2026-04-18）

### 问题现象

在 `-f1` 手动模式下，机器人可以正常响应键盘遥控，但裁判盒无法稳定识别机器人在线状态。

### 根因定位

文件：`src/controller/player/player.cpp`

在 `Player::run()` 中，`controlflag=1` 进入 `play_manual()` 分支后，绕过了原自动分支里的 `GcretTask` 周期调度；
而裁判盒识别依赖机器人持续发送 `RoboCupGameControlReturnData` 回传包，因此出现“可遥控但裁判盒不识别”。

### 修复方案

采用最小侵入修复：

1. 在 `controlflag=1` 分支补充与自动模式一致的 GC 回传周期（保持原频率条件不变）。
2. 仅补回传，不改变手动模式下的动作控制策略，不改变 remote 分支行为。

### 修复文件

- `src/controller/player/player.cpp`

### 验证要点

1. `-f1` 下：键盘 `wasdqe` 与 `k` 行为保持正常。
2. `-f1` 下：裁判盒可持续识别机器人（不再掉线）。
3. `-f0` 下：自动模式行为不变。

### 结论更新

该问题已通过代码修复：手动模式保留遥控能力，同时恢复裁判盒识别所需的回传心跳。
