# 2026-04-15 HD720采集 + 1:1中心裁剪 + 640x640下采样实施记录

## 背景
上一轮链路为“HD720采集 + 4:3中心裁剪 + 640x480下采样”。

当前新需求是：

1. 在 720P 采集基础上，将图像处理为 640x640。
2. 在“无黑边”约束下，尽可能保留摄像头的可用识别视野。

## 方案选择
本轮对比两种可行路径：

1. 保视野 letterbox：1280x720 直接 letterbox 到 640x640，可保留完整视野，但存在上下 padding。
2. 纯裁剪无黑边：1280x720 先做 1:1 中心裁剪到 720x720，再缩放到 640x640，无 padding。

最终采用方案 2（纯裁剪无黑边），原因：

1. 满足“640x640无黑边”目标。
2. 几何链路更直接，后续调试更稳定。
3. 在无黑边前提下，1:1中心裁剪可保留最大的中心有效视野。

## 代码改动

### 1) Camera：ZED 标定映射目标切换到 640x640
文件：src/controller/player/sensor/camera.cpp

关键变更：

1. 新增 ZED 专用目标尺寸常量：640x640（不改变 V4L2 的配置尺寸语义）。
2. ZED 标定映射按 1:1 目标宽高比重新计算中心裁剪窗口（1280x720 -> 720x720）。
3. `fx/fy/cx/cy` 按“中心裁剪 + 缩放到640x640”重新映射。
4. 启动日志中的 `target` 改为 640x640，便于快速核验当前链路配置。

### 2) Vision：引入运行时处理尺寸，隔离 ZED 与 V4L2
文件：

- src/controller/player/vision/vision.hpp
- src/controller/player/vision/vision.cpp

关键变更：

1. 新增运行时处理尺寸成员 `proc_w_`、`proc_h_` 与缓冲容量字段。
2. 在 `updata()` 中按数据源设置处理尺寸：
   - ZED：640x640
   - V4L2：沿用配置尺寸（当前为 640x480）
3. 裁剪比例计算改为基于处理尺寸宽高比：ZED 时目标宽高比固定为 1:1。
4. 运行日志增加 `proc=` 字段，标明本帧处理尺寸。

### 3) Vision 运行链路：ZED 固定为 1:1裁剪后缩放
文件：src/controller/player/vision/vision.cpp

关键变更：

1. `run()` 中读取当前 `proc_w_/proc_h_` 作为本帧处理尺寸。
2. ZED 路径改为：
   - `dev_bgr_ -> center crop(720x720) -> resize(640x640)`
   - `cudaUndistort` 在 640x640 尺度执行
   - 后续再进入 letterbox 到网络输入（保留对任意 engine 输入尺寸兼容）
3. 非 ZED 路径保持原行为，只是统一走处理尺寸变量。
4. 调试图像发送 `Mat` 尺寸与 `cudaMemcpy` 字节数改为基于 `proc_w_/proc_h_`，避免 640x480/640x640 混用。
5. 检测后处理输入原图尺寸参数改为 `proc_w_/proc_h_`。

### 4) 缓冲容量调整：兼容 ZED 640x640
文件：src/controller/player/vision/vision.cpp

关键变更：

1. `start()` 阶段 `dev_ori_`、`dev_undis_`、`dev_yuyv_` 分配改为容量分配（至少覆盖 640x640）。
2. 运行时拷贝字节数按当前处理尺寸计算，避免容量不足。

## 当前链路（ZED）

1. ZED 输出：1280x720 BGR
2. CUDA 中心裁剪：720x720（1:1）
3. CUDA 下采样：640x640
4. 去畸变：`cudaUndistort`（参数按 640x640 映射）
5. Letterbox 到网络输入尺寸（若引擎为 640x640，则 pad 为 0）

## 预期收益

1. 输出无黑边：640x640 纯内容输入，避免 padding 对观测与调试干扰。
2. 几何一致性提升：标定内参与运行处理尺寸统一到 640x640。
3. 回退兼容性更好：仅变更 ZED 路径，V4L2 维持原有尺寸行为。

## 风险与注意事项

1. 视野取舍：1:1中心裁剪会丢失 16:9 图像左右两侧边缘视野。
2. 建议重点验证：
   - 边缘区域目标（尤其门柱）是否存在漏检上升
   - 640x640 下里程计/测距是否存在系统偏差
3. 若后续实测发现边缘目标损失明显，可再评估切换为“保视野 letterbox 模式（可配置）”。

## 验证建议

1. 启动日志核验：确认 ZED 显示 `capture=1280x720`、`crop=720x720`、`target=640x640`。
2. 调试图核验：确认发送图像为 640x640 且无黑边。
3. 检测稳定性核验：关注球与门柱在图像边缘的识别连续性。
4. 几何核验：执行点选测距与在线里程计对比，确认无明显系统漂移。
5. 回退核验：模拟 ZED 打开失败，确认 V4L2 路径仍可正常工作。

## 本次结论
本轮已完成“HD720采集 + 1:1中心裁剪 + 640x640下采样”代码落地，且改造范围限定在 ZED 主路径。该实现满足“无黑边640x640”目标，并在约束条件下保持尽可能大的中心有效视野。
