# 2026-03-27 删除MV并切换ZED优先实施记录

## 背景
在保持现有视觉架构不变（Camera 采集 + Vision 推理）的前提下，完成两项目标：
1. 删除所有 MindVision（MV）相关代码与构建依赖。
2. 调整摄像头优先级为 ZED-mini 优先，失败后自动回退 V4L2。

## 本轮改造范围
- src/controller/player/sensor/camera.hpp
- src/controller/player/sensor/camera.cpp
- src/controller/player/vision/vision.hpp
- src/controller/player/vision/vision.cpp
- src/controller/player/sensor/CMakeLists.txt

## 关键改动

### 1) Camera 后端收敛为 ZED/V4L2 双路径
- 移除 `CameraApi.h` 依赖及全部 MV 相关成员与接口。
- 删除 `use_mv_`、`use_mv()` 与 MV 专属尺寸分支。
- `buffer()` 与 `camera_size()` 仅保留：
  - ZED：BGR，`w*h*3`
  - V4L2：YUYV，`w*h*2`

### 2) 设备选择顺序改为 ZED 优先
`Camera::open()` 逻辑重排：
1. 优先尝试打开 ZED-mini，并读取左目标定参数。
2. ZED 失败（或未编译后端）则回退 V4L2。
3. V4L2 分辨率采用配置 `image.width/image.height` 发起协商，再以驱动返回值为准更新 `w_/h_`。

### 3) 删除 MV 采集与控制逻辑
- 删除 `CameraSdkInit/Enumerate/Init/GetImageBuffer/Release/UnInit` 全链路调用。
- `set_camera_info` 保留配置缓存更新，不再执行 MV 运行时曝光/增益控制。

### 4) Vision 输入链路改为仅识别两类源格式
`Vision::run()` 内删除 MV 分支后，输入判定为：
- `src_size == w*h*2`：按 V4L2 YUYV 走 `cudaYUYV2BGR`
- `src_size == w*h*3`：按 ZED BGR 走 D2D 直拷贝
- 其他尺寸：记录错误并安全返回

去畸变策略保持：
- ZED：启用 `cudaUndistort`
- V4L2：保持无去畸变（原始行为）

### 5) 安全性补强
- Vision 构造函数中将 GPU/CPU 缓冲指针与尺寸字段全部显式初始化。
- `Vision::updata()` 增加相机尺寸合法性检查。
- 当 `camera_size` 变化时，自动释放并重建 `camera_src_/dev_src_/dev_bgr_`，避免越界。
- 拷贝前检查 `sptr->buffer()` 非空。

### 6) V4L2 缓冲生命周期修正
- `VIDIOC_REQBUFS` 后使用驱动实际返回的 `req.count` 作为缓冲数量。
- 释放时按 `buffer_count_` 遍历，不再硬编码 4，避免越界与潜在内存错误。

### 7) 构建系统去 MV
- 从 `src/controller/player/sensor/CMakeLists.txt` 删除 `MVSDK` 链接项。

## 验证结果

  - `use_mv_`
  - `CameraApi.h`
  - `CameraSdk*`

- VS Code 问题检查：本轮修改文件未发现语法/语义错误。

## 风险与后续建议
1. 当前 V4L2 回退仍依赖 `image.dev_name`，如果设备节点变化，建议后续做自动枚举。
2. 若未来支持运行时热切换后端，建议将 Camera 输出帧元信息（像素格式/stride）结构化，减少 Vision 侧对 `src_size` 的推断耦合。
3. 可在目标设备做 start/stop 压力测试，重点观察显存与 fd 释放稳定性。
