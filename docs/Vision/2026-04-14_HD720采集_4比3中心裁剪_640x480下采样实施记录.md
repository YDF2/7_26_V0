# 2026-04-14 HD720采集 + 4:3中心裁剪 + 640x480下采样实施记录

## 背景
当前链路存在两个问题：

1. ZED 采集端曾以低分辨率或直接拉伸方式进入视觉链路，细节损失明显。
2. 16:9 到 4:3 的非等比例缩放会带来形变，影响检测与几何一致性。

本次改造目标：

- 采集提升到 HD720（1280x720）
- 在 Vision 链路中做 4:3 中心裁剪
- 最终等比例下采样到 640x480（与训练图像尺寸一致）

## 方案选择
对比两种方案：

1. Camera 侧先裁剪缩放：改动集中在相机线程，但增加 CPU 处理压力。
2. Vision 侧 GPU 裁剪再缩放：充分利用现有 CUDA 图像链路，性能更稳，后续维护更统一。

最终采用方案 2。

## 代码改动

### 1) Camera：改为 HD720 原始采集并修正内参映射
文件：`src/controller/player/sensor/camera.cpp`

关键变更：

1. ZED 初始化分辨率从 `VGA` 调整为 `HD720`。
2. 相机缓冲按 HD720 分配，避免在 Camera 线程内强制缩放到 640x480。
3. 标定参数改为按“中心裁剪 + 目标尺寸缩放”映射到最终 640x480：
   - 先按目标宽高比计算中心裁剪窗口
   - 再对 `fx/fy/cx/cy` 做裁剪偏移与比例缩放
4. 启动日志新增 `capture/target/crop/crop_xy` 字段，便于确认链路配置。

### 2) ImageProc：新增 CUDA 中心裁剪接口
文件：

- `src/lib/imageproc/imageproc.hpp`
- `src/lib/imageproc/imageproc.cu`

关键变更：

1. 新增 `cudaCropCenter(...)` 声明与实现。
2. 新增 `crop_center_u8_kernal`，执行 BGR packed 图像中心裁剪。

### 3) Vision：接入中心裁剪节点
文件：

- `src/controller/player/vision/vision.hpp`
- `src/controller/player/vision/vision.cpp`

关键变更：

1. 新增裁剪相关成员：`dev_crop_`, `crop_size_`, `crop_w_/crop_h_/crop_x_/crop_y_`。
2. 在 `updata()` 里根据源图与目标图宽高比计算裁剪窗口，并分配 `dev_crop_`。
3. 在 `run()` 里将流程改为：
   - ZED 路径：`dev_bgr_ -> center crop -> resize to 640x480`
   - 非 ZED 路径：保留原先直接 resize。
4. 在 `stop()` 中释放新增的 `dev_crop_` 设备内存。

## 当前链路（ZED）

1. ZED 输出：1280x720 BGR
2. CUDA 中心裁剪：960x720（4:3）
3. CUDA 下采样：640x480
4. 去畸变：`cudaUndistort`（参数已按最终尺寸映射）
5. Letterbox 到网络输入尺寸（由 engine shape 决定）

## 预期收益

1. 图像清晰度提升：HD720 采集保留更多细节后再下采样。
2. 几何更稳定：避免 16:9 直接拉伸到 4:3 的形变。
3. 处理链路更统一：裁剪/缩放都在 Vision 的 CUDA 链路内完成。

## 风险与注意事项

1. 若 ZED 在某些环境下无法稳定开到 HD720，将回退到 V4L2 路径。
2. 由于新增裁剪缓冲，需关注显存占用和释放时机。
3. 建议重点验证以下内容：
   - 启动日志中的 `capture/crop/target` 是否符合预期
   - 检测框位置是否稳定
   - 点选测距与里程计几何是否无系统性偏移

## 本次结论
本次改造已完成代码落地，采用“HD720采集 + Vision侧4:3中心裁剪 + 640x480下采样”的实现路径。该方案在清晰度、几何一致性和可维护性上优于 Camera 侧直接缩放方案。
